# `reporting.py`

## Назначение

Модуль преобразует расчётные DataFrame в менеджерскую, диагностическую и
контрольную отчётность, записывает Excel и при запросе строит DAG-граф аномалий.

## Функции подготовки таблиц

| Функция | Результат |
|---|---|
| `build_manager_summary` | Краткий вывод, топ выбранных аномалий и структурные изменения |
| `build_history_for_selected` | История выбранных сегментов с долей в total |
| `build_missing_zero_report` | Сегменты с пропущенными или нулевыми неделями |
| `build_control_table` | Контрольные счётчики pipeline и Set Packing |
| `build_anomaly_analysis_sheet` | Все сегменты, прошедшие первичный фильтр, и причины отбора |
| `build_ratio_analysis_sheets` | Long-анализ долей и отдельно выбранные Set Packing строки |
| `highlight_manager_rows_on_anomaly_analysis` | Зелёная заливка менеджерских строк |
| `build_anomaly_tree_from_excel` | PNG/SVG/PDF по листу анализа |
| `write_anomaly_excel` | Финальная запись 11 листов |

## Менеджерский вывод

`build_manager_summary` создаёт:

1. Заголовок с total GMV текущей недели.
2. Краткий вывод по первой выбранной аномалии либо сообщение об отсутствии.
3. До `max_manager_facts` строк выбранных аномалий; значение обязано быть не
   меньше 1, иначе построение отчёта останавливается с `ValueError`.
4. Дополнительный раздел «Изменение структуры» для всех нетotal-кандидатов со
   состоянием `новый`, `возобновившийся`, `исчезнувший`.

Структурные изменения берутся из diagnostics и не обязаны быть выбраны Set
Packing. Это отдельный информационный блок.

Для каждой строки доступны `Delta GMV`, z-score и WoW-проценты GMV,
TX/AU/AM/AOV/TPM/Freq. Проценты с нулевой базой или неопределённым предыдущим
либо текущим ratio-значением выводятся пустыми.
Направление интерпретации определяется знаком `wow_delta_gmv` и формулируется
как рост/снижение относительно предыдущего периода; сравнение с прогнозным
«ожидаемым уровнем» не выполняется.

## Лист «Анализ аномалий»

Включает только строки с `passes_initial_anomaly_filter=True` и достаточным
`abs(wow_delta_gmv)`. На лист выводятся:

- сегмент, глубина, z-score, base/final score;
- число eligible-потомков и физически перечисленных групп;
- состав ID сильнейшей mixed-level группы как JSON-массив, её размер и score;
- `U`, доминирующая доля, `B_max`, `B_eff`, итоговый balance, coherence и
  hierarchy-коэффициент;
- для единственного сильного потомка: атомарный `capture`, совпадение
  направления, score родителя до cap, граница cap и признак его применения;
- selected/resolved;
- component, solver, gap, диапазон score компоненты и Set Packing reason;
- конфликты и число выбранных атомов;
- номер попадания в менеджерский top;
- причина отсутствия в менеджерском выводе;
- `Delta GMV`.

Сортировка: глубина ↓, `anomaly_score` ↓, `Delta GMV` ↓, сегмент ↑.
Строки менеджерского top выделяются зелёным.

## Excel-контракт

`write_anomaly_excel` создаёт 11 листов. Первые девять сохраняют GMV-семантику:

| Лист | Содержимое |
|---|---|
| `00_Параметры_и_контроль` | Пороги запуска и контроль |
| `01_Менеджерский_вывод` | Бизнес-резюме |
| `02_Итог_аномалий` | Выбранные Set Packing аномалии |
| `Анализ аномалий` | Прошедшие первичный фильтр кандидаты |
| `03_История_top` | Недельная история выбранных |
| `04_Диагностика_кандидатов` | Полная diagnostics |
| `05_Пропуски_и_нули` | Data-quality отчёт |
| `06_Контроль` | Контрольные показатели |
| `07_Журнал_set_packing` | Журнал оптимизации |
| `Анализ долевых метрик` | Long-таблица eligible-кандидатов и lifecycle-изменений; GMV нет |
| `Аномалии долевых метрик` | Только выбранные Set Packing долевые сегменты |

Long-листы долей сохраняют одновременно рабочие exact-поля и legacy-диагностику:

- `exact_global_net_contribution`, `exact_global_gross_contribution`,
  `exact_materiality_share` — вклад относительно Total и materiality;
- `hierarchy_parent_exact_metric_delta`,
  `hierarchy_parent_exact_gross_contribution`,
  `hierarchy_single_child_exact_net_contribution` — parent-relative dominance;
- `legacy_materiality_share`, `legacy_hierarchy_movement` — прежние значения
  для сопоставления результатов миграции.

На всех листах фиксируется первая строка, включается autofilter, ширина колонок
оценивается по первым 200 строкам и ограничивается диапазоном 10–48.

Состав листов защищён `test_pipeline_excel_sheet_contract`.

## Контрольные показатели

Среди прочего `build_control_table` считает:

- исходные и панельные строки, число недель;
- текущую/предыдущую дату и текущий total GMV;
- кандидатов, eligible и выбранных;
- unresolved/not proven;
- число атомов и уникально покрытых выбранных атомов;
- `double_count_violation_count`;
- global status, компоненты, non-optimal компоненты;
- objective и число конфликтных пар;
- число строк, восстановленных как пропуски.

## Граф аномалий

`build_anomaly_tree_from_excel` по умолчанию читает лист `Анализ аномалий`. Для долей
функция параметризована по `metric_name`, колонке/подписи дельты, признаку Set Packing и колонкам
числителя/знаменателя и их абсолютным межнедельным дельтам. Пилотный граф
`authzone_tx_share` показывает дельту доли в п.п., текущие числитель/знаменатель,
`Δ числителя`, `Δ знаменателя` и `Contribution` — точный аддитивный вклад
сегмента в изменение доли Total по формуле exact contribution (в п.п.).
Выбранные узлы имеют толстую рамку. Родитель зачёркивается, если его единственный
eligible-ребёнок проходит dominance rule (`capture ≥ 80%` и совпадает направление);
это не зависит от того, был ли cap численно связывающим.
Файл долевого графа задаётся `config.RATIO_TREE_OUTPUT_PATH` и не зависит от GMV-пути.

Обязательные колонки: `сегмент`, `глубина`, `z_scope`, `anomaly_score`,
`Delta GMV`.

Алгоритм:

1. Удаляет total/пустые и дубли `(глубина, сегмент)`.
2. Парсит `segment_key` в feature set.
3. Соединяет только соседние глубины `d → d+1`, если признаки родителя —
   строгое подмножество признаков ребёнка.
4. Получает ориентированный DAG: у ребёнка может быть несколько родителей.
5. Несколькими barycenter-проходами сближает связанные узлы и группирует
   родителей общих детей.
6. Разводит рёбра отдельными портами и трассами.
7. Кодирует знак `ΔGMV` цветом узла, manager membership — толстой рамкой,
   изолированный узел — пунктиром. Карточка с подписью «Доминирующий ребенок»
   или «Доминирующий ребенок cut» дополнительно перечёркивается серым крестом:
   это означает, что аномалию сегмента объясняет один дочерний сегмент.

Поддерживаемые форматы: `.png`, `.svg`, `.pdf`. Matplotlib работает через
headless backend `Agg`.

## Побочные эффекты и ошибки

- `write_anomaly_excel` перезаписывает output-файл.
- Граф создаёт родительские директории.
- Отсутствующий matplotlib вызывает `ImportError`.
- Пустой/несовместимый лист или неподдерживаемое расширение вызывают `ValueError`.
- Изменение названий колонок листа анализа требует синхронного изменения
  `build_anomaly_tree_from_excel`.
