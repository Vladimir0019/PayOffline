# `main.py`

## Назначение

Безаргументная точка запуска пакета. Модуль не содержит бизнес-логики и не
разбирает CLI-аргументы: все значения берутся из `config.py`, затем одним
вызовом передаются в `pipeline.run_pipeline`.

Запуск:

```powershell
python -m gmv_anomaly
```

## Поток выполнения

1. Импортирует пути, фильтр периода, dimensions, текущую дату, пороги и путь
   графа из `config.py`.
2. Вызывает `run_pipeline(...)` со всеми параметрами явно.
3. Из результата использует только таблицу `control`.
4. Печатает пути отчёта/графа и три контрольных числа:
   `candidate_count`, `selected_count`, `double_count_violation_count`.

## Контракт

| Вход | Выход |
|---|---|
| Глобальные значения `config.py` | Файлы создаёт pipeline; `main()` возвращает `None` |

Исключения `ValueError`, `ImportError`, `OSError` не перехватываются и должны
останавливать процесс с исходной диагностикой.

Если `TREE_OUTPUT_PATH` задан без расширения, в сообщении пользователю
добавляется `.png`; фактическое поведение совпадает с `reporting.py`.

## Зависимости

- `config.py` — единственный источник параметров безаргументного запуска;
- `pipeline.py` — вся orchestration;
- `__main__.py` и compatibility wrapper `Anomaly.py` вызывают `main()`.

## Что проверять при изменениях

- Не добавлять второй источник значений помимо `config.py`.
- При добавлении параметра синхронно обновлять `config.py`, сигнатуру pipeline,
  вызов в `main.py` и тест `test_main_uses_only_config_values`.
- Не переносить сюда расчёты или форматирование отчёта.
- После изменений запускать пакетные регрессионные тесты.
