# Локальные инструкции для `gmv_anomaly`

Перед анализом или изменением пакета сначала прочитай [`docs/_index.md`](docs/_index.md).
Затем открой только страницу нужного модуля из таблицы маршрутизации в индексе.

Правила поддержки документации:

1. Источник истины — код и регрессионные тесты. Документация объясняет контракт, но не заменяет проверку реализации.
2. Канонический контракт входных данных — [`docs/data_preparation.py.md`](docs/data_preparation.py.md).
   При расхождении с другими страницами верны он и код `data_preparation.py`.
3. Логику формирования витрины описывает [`docs/pred_insight.yql.md`](docs/pred_insight.yql.md).
4. При изменении формул, порогов, покрытия или оптимизации обнови соответствующую страницу в `docs/`.
5. Не заводи новые md-файлы: дополняй существующую страницу нужного модуля.
6. После изменений запускай:

   ```powershell
   python -m unittest gmv_anomaly.test_gmv_anomaly_refactor
   ```

Отдельные страницы намеренно не заведены для `__init__.py`, `__main__.py`,
`config.py`, `Anomaly.py`, `pipeline.py`, `segment_keys.py` и
`test_gmv_anomaly_refactor.py`. Их роль описана в индексе и на страницах
вызываемых модулей.
