# Локальные инструкции для `gmv_anomaly`

Перед анализом или изменением пакета сначала прочитай [`docs/_index.md`](docs/_index.md).
Затем открой только страницу нужного модуля из таблицы маршрутизации в индексе.

Правила поддержки документации:

1. Источник истины — код и регрессионные тесты. Документация объясняет контракт, но не заменяет проверку реализации.
2. При изменении входного контракта сначала сверься с [`docs/pred_insight.yql.md`](docs/pred_insight.yql.md).
3. При изменении формул, порогов, покрытия или оптимизации обнови соответствующую страницу в `docs/`.
4. Новые риски бизнес-логики фиксируй в `REFACTORING_FINDINGS.md`, а краткое резюме — в `docs/refactoring-findings.md`.
5. После изменений запускай:

   ```powershell
   python -m unittest gmv_anomaly.test_gmv_anomaly_refactor
   ```

Отдельные страницы намеренно не заведены для `__init__.py`, `__main__.py`,
`config.py`, `Anomaly.py`, `pipeline.py` и `test_gmv_anomaly_refactor.py`.
Их роль описана в индексе и на страницах вызываемых модулей.
